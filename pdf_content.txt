Theme Architecture: Exclusive Dark Mode Application Ecosystem  
 Executive Summary  
The Nexora AATS (Audit, Accounting, and Tax Suite) v4.0 application operates exclusively within a modern, deep -tone 
Dark Mode visual architecture. To enhance cognitive orientation, streamline navigation, and establish immediate 
visual context across comple x professional workflows, this specification defines an exhaustive Role -Based Color 
Theme System.  
By assigning distinct visual identities to specific operational modules — Audit & Assurance, Secretarial & Advisory, Tax 
Filing, All Roles (General Practitioner), and Administrator — the system ensures that users instantly recognize their 
operational conte xt without sacrificing universal brand cohesion, accessibility compliance, or ergonomic comfort 
during prolonged professional use.  
In accordance with system governance standards, the Administrator module directly adopts the active Core Blue 
Theme currently deployed across the platform, providing seamless continuity for administrative control and system 
configuration.  
 Part I: Architectural Framework & Design Philosophy  
1. Theme Overview  
1.1  Design Philosophy & Core Principles  
The AATS role -based color system is built upon three foundational ergonomic principles:  
● Cognitive Anchoring: High -frequency accounting and legal tasks require sustained focus. Color accents are 
used as contextual anchors rather than decorative clutter, allowing professionals to subconsciously register 
which compliance domain they are operatin g in.  
● Harmonious Dark Mode Depth: To prevent visual fatigue over 8 –10 hour workdays, background surfaces 
avoid pure black (#000000). Instead, the architecture utilizes layered, rich navy -slate shadows (#020617 to 
#1E293B) that absorb ambient glare while providin g distinct elevation cues via luminance separation.  
● Semantic Cohesion: While each role possesses a unique primary and accent identity, all functional semantics 
(success, warning, error, info, disabled states) share a universal color vocabulary across all modules.

20. Accessibility Standards  
The AATS Role -Based Color System strictly enforces compliance with WCAG 2.1 Level AA standards, with critical 
financial data elements achieving Level AAA performance.  
Contrast Ratios  
● Primary Text on Backgrounds: All primary text (#F8FAFC, #F0FDF4, etc.) against base surfaces exceeds a 12:1 
contrast ratio (well above the 4.5:1 AA requirement).  
● Secondary Text on Cards: Secondary labels (#94A3B8, etc.) maintain a minimum 7.2:1 contrast ratio.  
● Interactive Button Text: Primary button text (#FFFFFF or dark #064E3B / #451A03) against primary role fills 
(#3B82F6, #10B981, #F59E0B, #4F46E5) guarantees a minimum 4.8:1 ratio.  
Color Blindness Accommodation (Deuteranopia & Protanopia)  ● Workflow states never rely on color alone. Every status indicator pairs a distinct color with an explicit text 
label, structured badge border, and unique iconography (e.g., checkmark for Approved, alert triangle for 
Overdue, ban sign for Rejected).  
Font Visibility & Legibility  
● In Dark Mode, font weights below Regular (400) are prohibited for body text to prevent background bleeding. 
Numerical financial tables must utilize tabular monospaced figures with SemiBold (600) headers to maximize 
rapid character recognition.

 Part VI: Governance & Future Expansion  
24. Future Expansion Guidelines  
As the Nexora AATS application suite expands to incorporate new specialized professional modules (such as Forensic 
Accounting, Wealth & Asset Management, or International Transfer Pricing), future design implementations must 
strictly adhere to the followin g governance protocol:  
1. Tonal Separation Protocol  
● Any new module must select a primary color hue (H in HSL) that is separated by at least 30 degrees on the 
color wheel from all existing primary hues (Admin Core Blue 217°, Audit Indigo 244°, Secretarial Green 161°, 
Tax Amber 38°, General Sky 199°).  
● Example: A future Forensic Accounting module should utilize a Deep Crimson / Rose identity (#E11D48 / HSL 
347°), while a Wealth Management module should utilize a Statutory Cyan / Teal identity (#06B6D4 / HSL 
189°).  
2. Luminance & Saturation Locking  
● To maintain visual harmony across the Dark Mode workspace, new primary colors must maintain an HSL 
Saturation between 75% and 90% and a Luminance between 45% and 55% for their base 500 token.  
● Background surfaces (PrimaryBackground, CardBg) must never use pure black or unrelated hues; they must 
be derived by tinting a pure dark slate (#020617) with exactly 4% to 6% of the module's primary hue.  
3. Strict Inheritance of Universal Status Semantics  
● Future modules are strictly prohibited from altering or overriding the universal status colors defined in 
Section 6. A success milestone in Wealth Management must use the exact same Emerald Green (#10B981) as 
an audit verification in Audit & Assurance.  
4. Implementation via Dynamic Token Binding  
● In Avalonia XAML or CSS root declarations, new themes must be instantiated by defining a new 
<ResourceDictionary x:Key="Theme_NewModuleName"> that maps the module's specific 50 –900 color 
tokens to the standardized semantic property names (RolePrimary -500, AppBackground, ElevatedCardBg, 
etc.), ensuring zero code refactoring is required in core UI components.
